**MATCHING STRATEGY:**
For each required tool, find the most compatible service using these criteria:

1. **Core Functionality (40% weight)**: Does the service accomplish the same primary goal?
   - Exact match = 100%
   - Similar functionality = 70-90%
   - Related but different = 50-69%
   - Unrelated = 0-49%

2. **Parameter Compatibility (30% weight)**: Can the tool requirements be satisfied?
   - Perfect parameter match = 100%
   - Most parameters available = 70-90%
   - Some parameters available = 50-69%
   - Few/no compatible parameters = 0-49%

3. **Output Usefulness (20% weight)**: Will the service output be valuable?
   - Perfect output format = 100%
   - Useful with minor processing = 70-90%
   - Requires significant processing = 50-69%
   - Not useful = 0-49%

4. **Activation Status (10% weight)**: 
   - Active service = 100%
   - Inactive but can be activated = 90%

**MATCHING RULES:**
- Match if overall compatibility >= 65%
- Be generous with semantic equivalence (e.g., "weather_data" matches "get_weather")
- Consider that parameters can often be adapted or optional
- Inactive services are acceptable if functionally compatible
- When in doubt, favor matching over creating new services

Return ONLY a JSON object mapping tool names to service IDs:
